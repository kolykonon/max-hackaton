# Отчёт проверки локального запуска

Дата: 2026-09-30. Исходная ревизия: `e143ace`; на момент проверки изменения
ещё не были закоммичены. Существовавшая до работы правка ежедневных уведомлений в
`backend/app/main.py` сохранена, каталог `output/` не изменялся.

## Что найдено и изменено

Исходно существовали postgres/backend/bot/web, long polling, Alembic и
идемпотентные сиды. Отдельных Redis, DATA API и очереди нет. Основные препятствия:
root в образах, отсутствующая готовность API/web, опубликованный порт БД,
неверная точка монтирования данных PostgreSQL 17, ручное имя бота и отсутствие
туннеля. Код открытия мини-приложения использует MAX `open_app`, не `WEBAPP_URL`.

Настроены два многоэтапных образа, ожидание готовности и автоматический импорт,
изолированная БД, локальный порт 8088, профиль туннеля и скрипты URL.
Добавлены проверка токена, определение username и healthcheck. Курсор polling
исправлен по контракту MAX: `marker` берётся из ответа, а не последнего события.
Сценарии, обработчики, модели данных и миграции не переписывались.
Существующие `uv.lock` и `package-lock.json` используются без обновления версий.

## Среда и метод

- macOS, Docker Engine 28.5.1, Compose v2.40.3-desktop.1.
- Сделан отдельный `git clone --no-hardlinks` в временный каталог. Поверх него
  перенесены проверяемые исходники; личный `.env` и `output/` не переносились.
- `.env` создан из нового примера; добавлен заведомо фиктивный токен.
- Изолированный Compose-проект `kaplya-review`; для pytest — ещё одна временная
  PostgreSQL-база. Существующие контейнеры других проектов не затрагивались.
- Реальный токен пользователя не использовался для запуска/проверки API.

## Вручную и открытые вопросы

1. Для проверки подготовить `.env` по примеру, вписать свой токен и запустить
   `docker compose --profile tunnel up --build`. Исходный `.env` пользователя
   намеренно не перезаписывался.
2. Для проверки внутри MAX передать адрес туннеля организаторам для привязки.
   `WEBAPP_URL` не используется, новый username определяется автоматически.
3. При необходимости закоммитить изменения, записать новый commit hash для слайда.
4. Уточнить лицензию справочника и дату исходной выгрузки; для production
   нужны отдельные интеграции и отключение демонстрационных режимов.

**ДОПУЩЕНИЯ:** локальный веб-порт 8088; тестовый браузерный пользователь 1;
беспарольная БД trust допустима только в отдельной локальной сети без host-порта;
дата снимка справочника 2026-09-27 принята по `verified_on`, точная дата выгрузки
не установлена. Производственный домен и реальные ключи не подбирались.

**Риски:** новый MAX-бот без привязанного мини-приложения может отклонить кнопку
`open_app` вместе с приветствием; это требует проверки организаторами. Браузерный
демопользователь не совпадает с аккаунтом MAX, поэтому чатовые уведомления при
отдельной веб-проверке не гарантируются. Смена точки монтирования БД требует
ручного дампа/восстановления при обновлении старого стенда. Пять минут подтверждены
для сборки в измеренных условиях, а не для суммарного первого запуска и не для
любой сети/машины. PowerShell и реальный чат остаются непроверенными.
