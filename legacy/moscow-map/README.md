# Капля — интерактивная карта донорства Москвы

Откройте **index.html** двойным кликом. Это автономный файл: CSS, JavaScript, названия и SVG-контуры встроены. Интернет, сборка, сервер и API-ключи не нужны.

В прототипе **132 района и 12 административных округов**, включая 8 районов Новой Москвы и 5 районов Зеленограда. Только территория города Москвы, без Московской области.

## Что работает

- Выбор любого района по контуру или из списка; название и округ в карточке.
- Поиск без учёта регистра, различия «е»/«ё» и дефиса/пробела.
- Фильтр по административному округу.
- Виды «Москва», «Новая Москва», «Зеленоград» и «Вся карта».
- Масштабирование кнопками и колесом мыши; перемещение мышью или одним пальцем. На телефоне для масштаба используются кнопки +/−.
- Независимая смена цвета выбранного района через четыре демостатуса.
- Кнопка «Определить мой район»: по разрешению браузера получает текущие координаты, находит район по исходным полигонам и показывает точку с приблизительной точностью. Обрабатывает отказ, ожидание, отсутствие геолокации и координаты вне Москвы. Координаты остаются внутри браузера и не отправляются на сервер.
- Сброс цветов в блоке «О карте»; изменения не сохраняются после перезагрузки.
- Выбор с клавиатуры через Tab и Enter/пробел; `/` переводит фокус в поиск, Escape снимает выбор и очищает поиск.

**Цвета вымышлены.** Они не отражают реальные запасы крови, дефицит или рекомендации. Донорские центры и медицинская статистика не добавлены.

## Файлы

- `index.html` — готовый самостоятельный HTML, можно отправить одним файлом.
- `moscow-districts.svg` — отдельная векторная карта с именованными контурами и SVG-подсказками. Панель и расширенная интерактивность находятся в HTML.
- `data/moscow-districts.geojson` — исходные географические контуры, свойства и версии OSM.
- `src/index.template.html`, `src/styles.css`, `src/app.js` — исходники интерфейса.
- `scripts/build.py` — воспроизводимая сборка HTML и SVG без сторонних зависимостей.
- `scripts/fetch_boundaries.py` — обновление геоданных напрямую из API OpenStreetMap. Нужен интернет только для обновления. Ответы кешируются в `/tmp/kaplya-osm-cache`.
- `data/SOURCES.md` — происхождение и лицензия геоданных.

Сборка: `python3 scripts/build.py`.

Для проверки геолокации используйте локальный сервер: `python3 -m http.server 4173 --bind 127.0.0.1`, затем http://127.0.0.1:4173. Браузеры требуют защищённый контекст для доступа к координатам; `localhost` и `127.0.0.1` подходят. При открытии HTML двойным кликом работа геолокации зависит от браузера.

## Подключение будущих данных

У каждого района есть стабильный идентификатор `properties.id`, соответствующий relation ID в OpenStreetMap. В SVG это `id="region-<id>"` и `data-id="<id>"`. Для раскраски на уровне округа можно использовать `data-okrug`.

В карточке намеренно нет клиник. В будущем их можно связать с районами по ID, а `status` получать из серверных данных вместо демонстрационной формулы в `scripts/build.py`. Географические координаты сохранены в GeoJSON. Геометрия SVG построена в локальной эквидистантной проекции с опорной широтой 55.7°, без условного переноса Зеленограда или Новой Москвы. Отдельные территории одного района и внутренние отверстия сохранены; для отверстий используется `fill-rule="evenodd"`.

Контуры предназначены для обзорного интерфейса, не для юридического определения границ. Источник — общественный географический проект OpenStreetMap; официальная кадастровая точность не заявляется.

## Проверки

- `node --check src/app.js` — синтаксис JavaScript.
- `python3 -m py_compile scripts/build.py scripts/fetch_boundaries.py` — синтаксис скриптов.
- Сборка проверяет количество районов. Выгрузка проверяет административный уровень, замкнутость колец и принадлежность внутренних отверстий полигонам.
- Структурно проверены все 132 уникальных SVG-контура, имена и соответствие GeoJSON; HTML не ссылается на внешние скрипты, шрифты или стили.

Ручная проверка: открыть HTML, выбрать район и сменить его цвет; найти «Коммунарка» и «Крюково»; переключить округа и виды; увеличить, перетащить и сбросить карту; проверить мобильную ширину. На `localhost` нажать «Определить мой район» и разрешить геолокацию, затем проверить название, точку и точность. Отдельно проверить отказ в доступе или тайм-аут.
