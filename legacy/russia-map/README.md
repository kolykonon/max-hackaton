# Капля — донорская карта России

Самостоятельное расширение московского прототипа. Основное приложение (`frontend/`, `backend/`) и исходный `legacy/moscow-map/` не изменены.

## Открыть

Из корня репозитория:

```sh
python3 legacy/russia-map/scripts/serve.py
```

Карта: http://127.0.0.1:4174/legacy/russia-map/

Исходная Москва: http://127.0.0.1:4174/legacy/moscow-map/

Другой порт: `python3 legacy/russia-map/scripts/serve.py --port 4175`.
Нужен Python 3.9+. Сервер привязан к localhost и обслуживает только два прототипа; `.env` и основное приложение недоступны. Файл нельзя запускать двойным кликом: браузеру нужен HTTP для загрузки модулей и геометрии. После запуска интернет не нужен для интерфейса: библиотеки, контуры и данные локальные. Ссылки на внешние первоисточники требуют интернета.

## Что реализовано

- Обзор России, переход к региону, точкам и карточкам учреждений. 85 контуров; 405 учреждений из 84 регионов. Камчатский край без учреждений отображается серым.
- Все восемь групп крови; отдельные детерминированные демостатусы. Цвета карты, точек, списков и карточек синхронизированы.
- Поиск по региону, городу, названию, адресу и ID без учёта регистра и «ё». Поиск всегда по всей стране, даже из выбранного региона.
- Фильтр центров по статусу. Он не меняет региональную сводку или знаменатель её расчёта.
- Масштаб, перетаскивание, колесо/жесты D3; кнопка общего вида. На мобильном — кнопки масштаба и перемещение пальцем. `/` — поиск, Enter/пробел — выбор, стрелки на сфокусированной карте — перемещение, `+/-` — масштаб, Escape — закрытие диалога/очистка поиска.
- Кластеры в экранных координатах: нажатие приближает; совпадающие или всё ещё тесные точки раскрывают список. Ни одна запись не теряется.
- 132 района Москвы загружаются при её выборе. Сводка района учитывает только учреждения, координаты которых удалось отнести к району. Нераспознанные адреса не назначаются районам; полный список региона сохраняется.
- Геолокация только по нажатию. Регион определяется по исходному подробному контуру, точность браузера показывается в метрах. Ближайшие учреждения ищутся во всём справочнике, независимо от административных границ; расстояния — по прямой. Координаты пользователя хранятся лишь в памяти страницы.
- Исходные контакты, часы, запись, тип учреждения, источники, статус проверки и примечания; пустые значения отмечены как отсутствующие. Запись через карту не обещается.

## Воспроизвести подготовку

Готовые данные уже включены. Node.js нужен только для пересборки геометрии и тестов:

```sh
cd legacy/russia-map
npm ci
python3 scripts/import_data.py
python3 scripts/fetch_boundaries.py
node scripts/build_geometry.mjs
python3 scripts/generate_demo.py
node scripts/finalize.mjs
npm test
python3 -m unittest discover -s tests -p 'test_*.py'
```

Фактически приложен CSV UTF-8 BOM с разделителем `;`, а не Excel. Исходник сохранён в `data/raw/blood_stations_russia.csv`. Импортёр также принимает путь к `.xlsx` (для этой ветки требуется `openpyxl`). Формулы не исполняются: Excel читается с `data_only=True`; инструкции в ячейках никогда не являются командами. Все исходные столбцы сохраняются в `raw`, пустые ячейки — `null`.

### Геокодирование

```sh
python3 scripts/geocode.py
python3 scripts/reassess_cache.py
node scripts/finalize.mjs
```

Для переданного набора все 405 адресов уже обработаны. Повторный запуск пропускает готовые ID; `reassess_cache.py` повторяет только локальную проверку существующих ответов. `coordinates.json` и полный кеш сохранены. Обычная пересборка карты не вызывает геокодер.

Однократный импорт использует [Nominatim](https://operations.osmfoundation.org/policies/nominatim/): один процесс/поток, блокировка параллельного запуска, интервал минимум 1,15 с между запросами, идентифицирующий User-Agent, кеш каждого успешного ответа (в том числе пустого), до трёх попыток для временных ошибок. HTTP 403/429 немедленно останавливают импорт; обход ограничений не выполняется. Для регулярных заданий публичный сервис не использовать: нужен собственный/согласованный провайдер через `GEOCODER_URL`. Поиск в UI полностью локальный и не делает запросов Nominatim.

Сначала запрашивается сочетание региона, города и адреса; затем, при отсутствии однозначного результата, структурированный город + улица/дом. Сохраняются URL запросов, источник координат, адрес ответа, OSM ID, дата геокодирования (не медицинских данных), качество и причина. Совпадение дома включает корпус/строение. При неоднозначных зданиях точка не ставится. Единственное здание и POI внутри его bounding box считаются одним адресом. Улица может дать только явно приблизительную точку; центр города никогда не принимается. Несовпадение региона отклоняется, кроме явно указанного в справочнике расположения областного учреждения в Москве/Санкт-Петербурге; другие расхождения требуют ручной проверки. Это защищает от одноимённых населённых пунктов в разных областях.

### Демостатусы и будущий API

`data/catalog.json` — справочник; `data/coordinates.json` — геокодирование; `data/demo-statuses.json` — отдельный статусный payload. Seed: `kaplya-russia-demo-v1`. SHA-256 от `seed:id:group`, первые 4 байта big-endian modulo 100: 0–14 unknown, 15–52 enough, 53–81 needed, 82–99 urgent. Алгоритм не зависит от порядка строк, времени, браузера или перезагрузки.

Адаптер `status-provider.js` отделяет загрузку статусов от UI. Будущий API может вернуть `{kind, groups, statuses: {[id]: {[group]: status}}}`. Сейчас разрешён только `kind: "demo"`: реальные медицинские сведения потребуют отдельного источника, метаданных актуальности и изменения подписей интерфейса. Нельзя просто убрать слово «демо» с вымышленных значений.

### Формула цветов

`need = needed + urgent`, `known = enough + needed + urgent`, доля `need / known`. Unknown исключён из знаменателя и показывается отдельно. Зелёный <25%, песочный ≥25% и <60%, коралловый ≥60%; known=0 — серый. Один urgent не переопределяет долю всего региона. Региональная агрегация использует регион справочника, районная — географическое попадание доступных точек. Фильтр центров не меняет эти правила.

### Геометрия и загрузка

Обзор — TopoJSON около 200 КБ. Полные 85 контуров не загружаются на старте: один GeoJSON на выбранный регион, с кешем в памяти. Для геолокации bounding box индекс отбирает кандидатов, затем загружаются их исходные полигоны. Москва отдельно загружает районы. Исходный справочник и все 405 центров загружаются сразу, чтобы поиск и ближайшие не зависели от сетевых запросов.

Проекция — равновеликая коническая Albers, центральный меридиан 100° E, стандартные параллели 50° и 70°, центр 60°. Отрицательные долготы Чукотки интерпретируются непрерывно по обе стороны 180°; координаты не переносятся в условные вставки. SVG строится через поточечную проекцию и evenodd заливку. Mapshaper строит общую топологию соседей и упрощает её weighted Visvalingam до 20% с `keep-shapes` после разбиения на отдельные полигоны; затем части собираются обратно. Сборка и тесты проверяют сохранение количества островов/частей. Полные исходные геометрии используются для определения региона и детализации.

## Ограничения

- 202 адреса требуют уточнения. Их нельзя считать географически отсутствующими учреждениями или размещать по центроидам городов. Приблизительные точки улиц могут искажать расстояние до центра.
- Базовые 83 контура — исторический набор OSM/GIS-Lab с метаданными 2013 года, скачанный 27.09.2026. Это не актуализированная административная или кадастровая база. Некоторые контуры могут отличаться от современных районов Москвы. Дата скачивания не выдаётся за дату географической актуальности.
- Крым и Севастополь добавлены отдельными контурами OSM для записей справочника, с пунктиром и пояснением спорного статуса. Геометрия не изменена ради названий справочника. Подробнее — `SOURCES.md` и «О границах» в интерфейсе.
- Справочник предоставлен пользователем; реальная актуальность контактов, часы и право перераспространения этих сведений независимо не проверены. Даты из него сохранены как исходные значения.
- Это демопрототип без маршрутизации, записи на приём и живой медицинской информации.

Проверки и сценарии: [`reports/VALIDATION.md`](reports/VALIDATION.md).
