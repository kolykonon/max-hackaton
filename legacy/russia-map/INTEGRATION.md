# Интеграция в основное приложение и продолжение разработки

Карта уже находится в том же Git-репозитории, в `legacy/russia-map/`. Ничего копировать из чата не нужно. Сейчас это самостоятельный статический прототип; рабочие `frontend/` и `backend/` не изменялись.

## Быстрый показ

Запуск: `python3 legacy/russia-map/scripts/serve.py`. Открыть http://127.0.0.1:4174/legacy/russia-map/.

Статический прототип можно публиковать отдельным URL вместе с локальными `vendor/`, рабочими JSON и контурами. Для временного показа внутри основного приложения допустим iframe с этим URL, но `localhost` нельзя использовать для пользователей опубликованного сайта. Нужен путь на сервере. Справочник, права на его публикацию и атрибуция OSM требуют сохранения и проверки владельцем данных.

## Полноценная интеграция React + FastAPI

1. Уже существует `frontend/src/pages/MapPage/MapPage.tsx`, маршрут `/map` в `frontend/src/App.tsx`. Сейчас страница использует `MapPlaceholder`, три условные зоны из `SPOTS` и заглушки масштаба/геолокации. Заменить это отдельным React-компонентом `RussiaDonorMap`, сохранив оболочку `Screen` и навигацию приложения. Код прототипа не стоит целиком вставлять через `innerHTML`.
2. Перенести чистые функции из `core.js` в TypeScript-модуль карты: агрегация, кластеризация, point-in-polygon, расстояния. SVG/слои выделить в компоненты; DOM/D3-слушатели и ResizeObserver создавать/удалять в effect. Состояние группы, региона, поиска и выбранного центра хранить в React. Повторно использовать существующие UI-компоненты, где они подходят, и убрать глобальные стили прототипа.
3. Подготовленные `overview.topo.json`, `regions-index.json`, `regions/`, `moscow-districts.geojson` разместить в `frontend/public/maps/russia/` или на статическом сервере. Сохранить загрузку детализации по региону и атрибуцию. Кеш геокодера и сырые большие файлы в клиентский bundle не включать.
4. Сопоставить внутренние ID прототипа `r1…r85` с устойчивыми кодами приложения (`RU-MOW`, `RU-MOS` и т. п.) отдельным явным файлом. ID `rN` зависит от порядка исходной геобазы и не должен становиться долгосрочным бизнес-ключом API. Для спорных территорий сохранить отдельные флаги и согласованное правило отображения.
5. Импортировать учреждения через миграцию/seed в backend. В `backend/app/models/center.py` широта/долгота сейчас обязательные — сделать их nullable, иначе 202 нераспознанные записи будет невозможно честно сохранить. Добавить `source_id` (`BS-…`) с уникальным индексом, регион справочника, физический регион, город, тип учреждения, контакты, часы, способ записи, источники, качество координат и примечания. Нельзя подставлять 0/0 или центр города ради NOT NULL.
6. Статусы центра уже представлены `CenterBloodStatus` в `backend/app/models/blood_status.py`. Согласовать восемь групп и четыре статуса с существующими enum, включая «Нет данных». Хранить явный признак `demo`, источник и происхождение; не смешивать синтетические значения с реальными.
7. Существующий маршрут `backend/app/api/v1/map.py` (`/map/status`) и hook `frontend/src/api/hooks/regions.ts` — точки подключения. Проверить сервис агрегации и изменить контракт: отдавать total/known/need/unknown/urgent/ratio по группе, а не региональный статус по худшему центру. В `docs/openapi.yaml` описать модель, затем перегенерировать типы штатной командой frontend. Статический адаптер `status-provider.js` показывает, как отделён источник данных.
8. Подключить реальные центры к `frontend/src/components/features/booking-center/CenterMap/CenterMap.tsx` после проверки контрактов. Наличие телефона/строки «Запись» в справочнике само по себе не означает поддержку бронирования через API приложения.
9. Перенести тесты чистой логики и прогнать проверки основного frontend/backend. Проверить мобильную ширину, клавиатуру, загрузку геометрии, отсутствие утечки геолокации и обработку ошибок. Исходные оба прототипа оставить для сравнения.

## Сохранить работу и обновить кодовую базу

На момент подготовки инструкции текущая ветка — `main`; новая папка ещё не закоммичена. Следующие команды — инструкция, они автоматически не выполнялись. Сначала проверить `git status` и учесть другие изменения, если появились.

```sh
cd /Users/akarmain/MeGa/max-hackaton
git switch -c codex/russia-donor-map
git add legacy/russia-map
git commit -m "Add Russia donor map prototype and prepared data"
git fetch origin
git rebase origin/main
```

Так карта окажется отдельным коммитом поверх актуального `origin/main`. Если при rebase возникнут конфликты — разрешить их, проверить результат и выполнить `git rebase --continue`; вернуться в исходное состояние можно через `git rebase --abort`. Для уже опубликованной общей ветки вместо переписывания истории согласовать merge. Отправка на GitHub — отдельный шаг `git push -u origin codex/russia-donor-map`.

Дальше работать в той же ветке/репозитории. Перед интеграцией ещё раз проверить структуру свежей версии: указанные пути могут измениться после обновления. При новом clone прототип появится только после публикации соответствующей ветки/коммита.
